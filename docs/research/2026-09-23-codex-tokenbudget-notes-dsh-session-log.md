# Addendum: TokenBudget / Notes → DSH session log

## Decision and evidence boundary

This supersedes the **migration recommendation**, not the source findings, in `2026-09-23-codex-single-session-context.md`: the selected target is **model-visible budget + agent-authored notes + fresh context + historical reads**, NOT default local summarization. That report was read first. “Latest” here means the requested, locally verified SHA, not an assertion about today's upstream HEAD.

**Result:** Codex implements a fresh **window in the same durable thread**, not a new thread. Native Notes/history are authenticated backend tools, separate from the older MCP bridge. Public source proves the client protocol and its advertised normalized-history contract; it does **not** prove that the server exposes every original byte of all previous context. DSH can implement a stronger, locally testable retained-log read contract through plugins, without modifying official packages.

Evidence labels: **proven** = inspected client/installed code; **contract** = description/schema supplied by that code, not verified backend behavior; **proposal** = DSH design inference. No live provider calls or Rust tests were run. All upstream URLs below pin the requested SHA. ## 2. Native Notes/history: protocol, storage, and limits

**Proven tool inventory:** namespace `notes`: `list_files_by_prefix`, `read_file`, `search_contents`, `append_to_file`, `write_file`; namespace `history`: `list_windows`, `list_items`, `read_item`, `search_contents`. Each maps to HTTP POST `alpha/{notes|history}/v2/<action>` appended to provider base URL. These are not filesystem tools or a client SQLite notes database. [actions/endpoints:25-101](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L25-L101).

The extension injects `context:{session_id,current_agent_name}` into arguments, applies provider authentication, sends `x-openai-tool-output-truncation-policy`, and uses a 35-second timeout. The two search actions and two writers use `x-openai-encrypted-tool-arguments:true`; schemas mark query/text encrypted. Writers are not parallel tools. Server `encrypted_output` becomes opaque EncryptedContent; otherwise JSON becomes text; image attachments are separated. This is **not portable plaintext Chat Completions behavior**. [backend:14-91](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/backend.rs#L14-L91), [schemas:177-235](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L177-L235), [output:332-406](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L332-L406).

**Advertised Notes contract, not audited server storage:** virtual `<agent_name>/notes/<path>` paths; relative paths use current agent; no empty/`.`/`..` components or shell expansion; ≤1,000,000 UTF-8 bytes/file. `write_file` replaces, `append_to_file` appends exactly. Reads reflect successful writes immediately, but list/search are eventually consistent. Server storage implementation, retention, backup, and at-rest encryption are absent from this client. The tool description permits cross-agent writes, while bundled guidance says writes are current-thread-only: **do not implement authorization by guessing which prose wins**. [description:27-29](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L27-L29), [bundled guidance:105-112](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/models-manager/models.json#L105-L112).

### Is historical READ the entire original history?

**Not established.** The advertised object is **normalized history**, read-only and eventually consistent, ordered by persisted ordinal then creation time. It is fetched from the backend, not replayed from local rollout files by this extension. The client requests ingestion using `history_ingest_requested` in turn/compaction metadata; this is not an ingestion acknowledgement or completeness proof. [history contract:27](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L27), [ingest metadata:659-735](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/core/src/session/session.rs#L659-L735).

Recovery protocol: list windows → list/filter items → read item by **window_id + item_id**, optionally `offset_chars`/`limit_chars`; search is case-sensitive literal substring. Listings may return truncated content (`max_chars_per_item`). Unknown windows yield no matches. Tool responses request an output budget that the server applies before encryption. Thus “can retrieve prior content on demand” does **not** mean “loads all history into the next prompt,” “unlimited single read,” or “all raw tool stdout/media/reasoning preserved.” Server ingestion completeness, pagination exhaustion, opaque-item fidelity, and backend ACLs need separate acceptance tests. [schemas:143-190](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L143-L190), [output budget:333-343](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/tools.rs#L333-L343).

### Native hint ≠ MCP bridge

* Native extension fetches `alpha/notes/v2/thread_hint`, requires plaintext `text`, rejects >4000 bytes, and contributes a ContextWindow fragment; empty text contributes nothing. [extension:119-149](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/extension.rs#L119-L149).
* With native Notes **disabled**, TokenBudget and a known model window may call MCP server literally `notes`, tool `thread_hint`, with `_meta.threadId`; text chunks are joined into `<context_window>`. Native failure must **not** fall back to this bridge. Its external implementation/storage/full-history behavior is not proved by this call site. [session:4318-4375](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/core/src/session/mod.rs#L4318-L4375).

### Gates are layered, not one universal paid-account rule

1. Feature registry marks TokenBudget and ContextManagement under-development/default false. Explicit configuration and model metadata are separate activation paths; explicit preference/managed requirements can prevent model activation. [features:1677-1687](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/features/src/lib.rs#L1677-L1687), [activation:122-158](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/core/src/session/token_budget.rs#L122-L158).
2. ContextManagement **automatic** activation requires experimental-context model support, Codex-backend provider/auth configuration and ChatGPT Plus/Pro/ProLite. Do not apply that account test to all explicit TokenBudget use. [eligibility:13-58](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/core/src/session/token_budget.rs#L13-L58).
3. Native extension additionally requires `use_history_notes_extension`, `is_openai()` and current Codex-backend auth. Unsupported starting model with native Notes requested is an error. App-server installs the extension; other embedding registries must be checked rather than assuming all TokenBudget hosts install it. [extension gate:46-63](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/ext/history-notes/src/extension.rs#L46-L63), [model refusal:727-737](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/core/src/session/mod.rs#L727-L737), [app-server installation:74](https://github.com/openai/codex/blob/30fc6864cc1318121eca1843c217fe00ce1212f1/codex-rs/app-server/src/extensions.rs#L74).

## 3. DSH V3: what to read, and what not to confuse

| Surface | Installed evidence and meaning |
|---|---|
| Canonical retained log | V3: `P/dsh-session/lib/index.js:56`. `snapshotEvents(from,to)` is an immutable half-open seq-range snapshot; `ownEvents`/`isOwnSeq` distinguish fork-inherited prefix. `P/dsh-session/lib/types/index.d.ts:176-219`. |
| Current model history | `deriveMessages()` walks current surface; replacements shadow earlier nodes. It is **wrong for full historical read**. Append-origin events support human transcript; replacement nodes are model-only. `P/dsh-session/lib/types/index.d.ts:267-292`; `P/dsh-session/lib/types/surface.d.ts:25-64`. |
| Exact logical read | `ctx.sessionQuery.readSession(id)` returns cloned header, inheritedEventCount and complete events, validates with detached `Session.create`, does not resume/register an agent. `P/dsh-session-query/lib/index.js:1068-1081`; `P/dsh-session/lib/index.js:1036-1046`. Live-preferred corpus avoids persistence for live targets (`P/dsh-session-query/lib/types/corpus.d.ts:44-53`). |
| Cold read semantics | Opens read handle, reads full committed log, closes it, adds in-memory interrupted-turn closers. Those synthetic closers are **not original persisted events**; don't label this observation byte-identical disk export. `P/dsh-session-query/lib/index.js:21-52`. |
| Index/read API | `listEvents`, `filterEvents`, `readEvent`, `readSurface`, `traceSession`, `traceEvent`, plus session/title reads are public services: `P/dsh-session-query/lib/types/index.d.ts:35-150`. Exact readEvent before/after window defaults to 50 and rejects oversize; whole-log read/list/filter do not apply that truncation. `P/dsh-session-query/lib/index.js:8,1135-1168,1202-1231`. |
| Search is optional | Shipped base/Web composition sets SQLite `openAt: never`; indexed search then throws `SESSION_QUERY_SEARCH_DISABLED`, while exact reads remain usable. This is a **composition declaration**, not a live-service probe of every profile override. `P/dsh-base/cordis.patch.yml:121-139`; `P/dsh-web-app/cordis.patch.yml:22-30`; `P/dsh-session-query-sqlite/lib/index.js:589-595`. `filterEvents` can scan without FTS (case-insensitive, whitespace-flexible text matching): `P/dsh-session-query/lib/index.js:739-744,779-780`. SQLite defaults: 20 results, max 100, 240-char snippets, `P/dsh-session-query-sqlite/lib/index.js:471-494`. |
| Raw file vs export | Backend default is `session.v3.jsonl.zstd`, not plain readable JSONL; `compression:none` is an alternative. Raw roots may contain older formats. Prefer services over filename parsing/decompression. `P/dsh-session-persistence-jsonl/README.md:74-98`; `P/dsh-session-persistence-jsonl/lib/index.js:2176,2288`. |
| User-readable artifact | `/api/session.export` GET/HEAD emits ZIP: current-format `session.v3.jsonl`, optional descendants and attachments. Serializer writes header + events; live log is flushed first. Browser chooses destination; this is not an already-exposed model history tool. `P/dsh-session-log-export/lib/index.js:63-112,243-297,463-530`. Host plugin can instead use `open(id,'read')` + `handle.read` directly. |
| Provider log upload | `dsh_session_log` is separate request metadata, **not model input and not a model retrieval capability**. `P/dsh-session-log-deepseek/README.md:46-59`. |

**Retention qualification:** DSH's compaction/pruner append replacements rather than erase original logged nodes (`P/dsh-compaction-basic/lib/index.js:598-632`; `P/dsh-compaction-tool-result-pruner/lib/index.js:126-180`). Full retained-log access therefore survives these rewrites. It cannot recover output already truncated by a tool before logging, deleted attachments, missing legacy data, or opaque provider content. “Entire previous context” needs a precise fidelity definition, not just a `readSession` call.

**Authorization/ownership:** read handles do not take writer ownership and can coexist with a writer (`P/dsh-session-persistence/lib/types/handle.d.ts:7-12`; `P/dsh-session-persistence/lib/types/index.d.ts:109-122`). The inspected query/read service accepts session ID with **no caller/parent authorization parameter/check**; export checks nonempty ID but no per-session ancestry. HTTP transport separately enforces Host/Origin and browser-session auth (`P/dsh-session-log-export/lib/index.js:502-520`; `P/dsh-client-connection/lib/index.js:199-215,552-556,576-601,768-781`). These fences are not model-level history ACLs. A plugin must bind allowed IDs to calling session and approved lineage; do not expose arbitrary host corpus IDs simply because the service can read them.

## 4. Feasible plugin-only mapping (proposal, not implemented)

Keep all changes in **dsh-codex-mode**, mount only in `agent-presets/codex/agent.cordis.yml`, replace its existing basic-compaction/pruner composition rather than modifying official npm files or stacking independent reset owners (current preset lines 131-156).

1. **Budget owner:** plugin uses `ctx.tokenMeter.measure(session, effectiveHeader)` and chosen model capacity to implement remaining-budget tool + threshold guidance. Meter is replay-aware, uses matching provider usage or heuristic repricing; it is not an exact tokenizer. `P/dsh-token-meter/lib/types/index.d.ts:25-46`; `P/dsh-token-meter/lib/types/types.d.ts:23-36`. Define total/body-after-prefix scope, output reserve and unknown-capacity behavior explicitly.
2. **Agent-authored Notes:** local plugin-owned durable store, explicit read/write/append tools, window IDs and acknowledged revision. Native Codex backend encryption and storage must not be claimed. Choose crash-safe storage and fork semantics before implementation; allow rollover only after confirmed note persistence if lossless task handoff is required.
3. **Fresh window, same Session:** tool records request; process at safe between-step boundary. `agent/pre-step` and request-error hooks already support pressure and overflow recovery (`P/dsh-compaction-basic/lib/index.js:788-845`). Session surface supports logged replacement with earlier-source provenance (`P/dsh-session/lib/types/index.d.ts:202-238`). A plugin can replace a balanced span with a small notes/history locator, not an LLM-generated summary. Maintain compaction locking/pairing/flush invariants; do not reset while a tool pair is incomplete.
4. **Rebootstrap is a real design gap:** systemPrompt/runtime context are assembled before the pre-step waterfall (`P/dsh-agent-loop/lib/index.js:885-907`). Removing old context nodes does not prove existing profile/world-state latches re-inject them. Explicitly test policy, skills, goals, OpenViking, active user task and pending input after rollover; do not call global clear or launch a new agent as a shortcut.
5. **History reader:** expose scoped list/search/read tools over original retained events, bounded by immutable `(sessionId, windowId, throughSeq)` and cursor/character offsets. Use `readSession`/event scans initially; do not depend on disabled FTS. Return explicit truncation and next cursor; separate original messages from replacement checkpoints, synthetic closers, internal events and attachment payloads. Retrieved text is historical data, not fresh user authorization. Read-only retrieval must never resume/fork the old agent.

The existing `CompactionEngine` seam describes one replacement summary node (`P/dsh-compaction/lib/types/index.d.ts:67-132`); a no-summary implementation must define honest replacement/checkpoint provenance and event accounting. Plugin feasibility is supported by hooks + surface APIs, **not yet demonstrated end-to-end**. New event vocabulary also needs supported version/replay handling; the format migration catalog is build-static (`P/dsh-session-format-catalog/README.md:47,95-96`), not an arbitrary plugin migration registry.

## 5. Crucial questions for the user grill

1. Does “new session” mean **fresh model window in one durable DSH Session** (Codex-equivalent, recommended), or a genuinely new Session ID/tab? The latter requires explicit parent/lineage, goal, tool-job, and authorization transfer contracts.
2. Does “entire history” mean all **retained original logged messages** on demand, or exact wire requests, pre-truncation stdout, all media and provider-private reasoning too? Which exclusions are acceptable?
3. Must rollover be blocked until the model writes notes and they are durably acknowledged? What if it ignores reminders, runs out of context, or note storage fails? Never silently substitute local summarization for the selected mode.
4. Which notes/history may a child read: self, ancestors, siblings, descendants? Can anyone write another agent's notes? Fork copies vs shared store? Upstream prose conflicts are not an authorization policy.
5. Should notes/budget/history tools be visible/exportable to the user? Upstream descriptions call Notes/history private model-only; a transparent local plugin need not reproduce that product choice.
6. What are budget threshold/reserve, minimum useful fresh window, retrieval page budget and overflow fallback? How do changed models/provider estimates alter these numbers?
7. Is local DSH functionality the goal, or actual private Codex backend parity? The latter has authentication/model/encrypted-protocol gates and server behavior that this public source cannot validate.

**Acceptance minimum:** write→flush→rollover→read old item exactly; large paged item and media reference; multiple windows; restart; fork authorization denial; no agent activation on read; pending tools/input; failed note write; canceled rollover; unknown model capacity; model switch; replay after replacement; original log retained after pruner; required context rebootstrap. These are required tests, not results claimed here.
